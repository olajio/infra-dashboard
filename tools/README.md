# Tools for MIM V3

The original build scripts lived outside the repo and were lost when the work environment was reset (14 Oct 2026).
Since then `MIM V3.ndjson` is changed by patch scripts kept here, so the work can be repeated and reviewed.

| File | What it does |
|---|---|
| `mim_v3_patch_2026-10-14.py` | The 14 Oct changes (suggestions2.txt): Active P1 / P2 donut, Users impacted demo number, banner removed, Middleware / Database tables, server named on Server Health, Applications on this CI and Changes on 7 days, link-only cards. `python3 mim_v3_patch_2026-10-14.py IN.ndjson OUT.ndjson` (run once, on the version before it) |
| `test_mim_v3_2026-10-14.py` | Loads small known data into a local Elasticsearch (localhost:9200) and checks the changed panels' queries as stored in the dashboard |
| `link_cols.py` + `check_link_columns.js` | Kibana 9.5 blocks links on columns a query creates. `python3 link_cols.py "MIM V3.ndjson" /tmp/linkpanels.json`, copy the JSON and the .js into the Kibana container as `/tmp/linkpanels.json` and `/tmp/check_link_columns.js`, then run `node /tmp/check_link_columns.js` there (Kibana's own `getQuerySummary` decides) |
| `mim_v3_patch_2026-10-15.py` | The 15 Oct fixes to the colleague's export (`updated mim dashboard.ndjson`): related-CI views with exact classes, both directions and the Incident / CI controls; extra control removed; 24 h default; sections expanded and renumbered; Application Health, Services of the Application and the Application control. `python3 mim_v3_patch_2026-10-15.py "updated mim dashboard.ndjson" "MIM V3.ndjson"` |
| `test_mim_v3_2026-10-15.py` | Checks those panels and settings against small known data in a local Elasticsearch |
| `mim_v3_patch_2026-10-16.py` / `test_mim_v3_2026-10-16.py` | The 16 Oct changes (suggestions2.txt update): people columns in Active Incidents and Escalate (Assigned MIM removed), Applications impacted and What this CI runs on removed, Open Alerts 24 h, Active P1 / P2 as a Vega donut, Users impacted text (both black until the second round below) |

| `mim_v3_patch_2026-10-16b.py` / `test_mim_v3_2026-10-16b.py` | The second 16 Oct round: CMDB status removed from the four section 3 views, Active P1 / P2 and Users impacted transparent with theme text colours, descriptions that named removed panels corrected. Run the 15 Oct test before this test (it loads the dependency data) |
| `mim_v3_patch_2026-10-16d.py` / `test_mim_v3_2026-10-16d.py` | P3 incidents included: Incident and CI controls, Active donut (P3 blue), Active Incidents, Escalate. Run after `mim_v3_patch_2026-10-16b.py`; the test cleans up its own data |
| `mim_v3_patch_2026-10-16e.py` / `test_mim_v3_2026-10-16e.py` | P3 target 24 h: Time to Resolve covers P1 / P2 / P3 (blue 24 h line; log axis, replaced by `-16g`), open incidents plotted by their age so far (the live P1 that did not show), one value per incident, points always drawn; Active Incidents compares a P3 without an SLA record with 24 h. Run after `mim_v3_patch_2026-10-16d.py` |
| `mim_v3_patch_2026-10-16f.py` / `test_mim_v3_2026-10-16f.py` | Active P1 / P2 / P3 donut: every non-zero priority gets at least 6 % of the ring (a small P2 slice was hidden by the gap between slices), the legend always lists P1 / P2 / P3, and the query uses the same active rule as Active Incidents. Run after `mim_v3_patch_2026-10-16e.py` |
| `mim_v3_patch_2026-10-16g.py` / `test_mim_v3_2026-10-16g.py` | Donut gets the same fixed panel range as Active Incidents (Kibana 9.5 applies the dashboard's time range to Vega ES\|QL by itself, so the donut followed the time picker and missed On Hold P2s); Time to Resolve axes from 0 h, P3 on its own right axis. Run after `mim_v3_patch_2026-10-16f.py` |
| `mim_v3_patch_2026-10-16h.py` / `test_mim_v3_2026-10-16h.py` | The four related-CI views move into section 2 after Blast radius and Applications that depend on this CI; the empty section 3 is removed and sections renumbered. Run after `mim_v3_patch_2026-10-16g.py` |
| `mim_v3_patch_2026-10-16i.py` / `test_mim_v3_2026-10-16i.py` | Related-CI panels read `cmdb-ci-relations*` (the full graph; last 5 years fixed; both directions; retired marked; case-insensitive name); *Applications related to this CI* replaces *Applications that depend on this CI* and *Application View*; *Other related CIs* catches every other class; Blast radius from the same graph; "Count" → "Times fired". Run after `mim_v3_patch_2026-10-16h.py` |
| `mim_v3_patch_2026-10-16j.py` / `test_mim_v3_2026-10-16j.py` | Application Health follows the selected CI (CMDB-linked business applications, APM services on the CI, or the CI itself; all production when nothing is selected); production only in the related-CI tables, Blast radius, Applications on this CI and Open Alerts with No Incident (blank environments kept); Short description back in Active Incidents; Changes moved after Escalate. Run after `mim_v3_patch_2026-10-16i.py` |
| `mim_v3_patch_2026-10-18k.py` / `test_mim_v3_2026-10-18k.py` | Server control and Health window: CI control also lists production servers; new Server and Health window (15 min … 7 days, default 24 h) controls; the health panels follow the incident's CI, else the CI control, else the Server control (whichever is first a server) over the Health window; Server Health becomes one row per server; Alerts on this CI also follows the server (7 days). Run after `mim_v3_patch_2026-10-16j.py` |
| `mim_v3_patch_2026-10-18m.py` / `test_mim_v3_2026-10-18m.py` | Servers column in *Application Health* (per application) and *Services of the Application* (per service): APM agent hosts in the last 15 minutes, up to 3 then "+N more"; Application Health's description explains its "Last 5 years". Run after `mim_v3_patch_2026-10-18l.py` |
| `mim_v3_patch_2026-10-18l.py` | Note in *Errors from the Logs* that a 3- or 7-day Health window can load slowly the first time (Round 11d). Run after `mim_v3_patch_2026-10-18k.py`; checked by `test_mim_v3_2026-10-18k.py` |

To rebuild `MIM V3.ndjson` from the colleague's export, run the patches in order:
`mim_v3_patch_2026-10-15.py "updated mim dashboard.ndjson" "MIM V3.ndjson"`, then `mim_v3_patch_2026-10-16.py "MIM V3.ndjson" "MIM V3.ndjson"`, then `mim_v3_patch_2026-10-16b.py "MIM V3.ndjson" "MIM V3.ndjson"`, then `mim_v3_patch_2026-10-16d.py "MIM V3.ndjson" "MIM V3.ndjson"`, then `mim_v3_patch_2026-10-16e.py "MIM V3.ndjson" "MIM V3.ndjson"`, then `mim_v3_patch_2026-10-16f.py "MIM V3.ndjson" "MIM V3.ndjson"`, then `mim_v3_patch_2026-10-16g.py "MIM V3.ndjson" "MIM V3.ndjson"`, then `mim_v3_patch_2026-10-16h.py "MIM V3.ndjson" "MIM V3.ndjson"`, then `mim_v3_patch_2026-10-16i.py "MIM V3.ndjson" "MIM V3.ndjson"`, then `mim_v3_patch_2026-10-16j.py "MIM V3.ndjson" "MIM V3.ndjson"`, then `mim_v3_patch_2026-10-18k.py "MIM V3.ndjson" "MIM V3.ndjson"`, then `mim_v3_patch_2026-10-18l.py "MIM V3.ndjson" "MIM V3.ndjson"`, then `mim_v3_patch_2026-10-18m.py "MIM V3.ndjson" "MIM V3.ndjson"`.
Tests: `test_mim_v3_2026-10-14.py`, `-16.py`, `-15.py`, `-16b.py`, `-16d.py`, `-16e.py`, `-16f.py`, `-16g.py`, `-16h.py`, `-16i.py`, `-16j.py`, `-18k.py`, `-18m.py`, each with `"MIM V3.ndjson"`, against a local Elasticsearch on port 9200 (since 16 Oct: Elasticsearch and Kibana 9.5.3 from Docker Hub, the cluster's version; set `cluster.routing.allocation.disk.threshold_enabled: false` if the disk is nearly full).
